# fix3：普通逐行歌词进度的句尾与切句衔接

日期：2026-10-05。分支：`feat/dynamic-artwork-provider`。
状态：用户已设备确认本次优化效果满意。原问题为前后句衔接较快时，上一句高光未扫满就跳句并回退；未提供本轮新复现日志。

2026-10-05 用户反馈：“可以，这版效果满意”。记录为 fix3 普通逐行歌词进度的句尾与切句衔接效果验收通过；
不扩大为所有播放器、长期稳定性或整个 C17 适配矩阵验收。

## 静态发现与改动

- 原高光活动句依赖官方 Recycler 索引，而进度依据播放时间。官方提前换行时，两者可能不同步。
  只对开启“普通逐行歌词进度”的亮屏 LINE_TIMED 行，改用播放时间选择高光所属句；
  原生滚动、焦点/缩放归属、逐字歌词与 AOD 原有活动句选择保持原路径。
- 原逐行进度走 WordRange 绘制分支；当未到开始时间、没有当前词索引时，存在整句高亮兜底。
  现在逐行进度直接按整句可见宽度推进，换行段共享同一个高光前沿，不依赖词索引；
  开始前保持 0，避免“整句亮起→从零扫亮”。紧凑布局使用相同策略。
- 可视扫亮终点从实际展示终点提前 `min(120ms, 句长/10)`，给句尾羽化留下全亮停留。
  下一句仍从其真实时间戳开始；不移动行时间、不伪造逐字时间轴、不让下一句提前唱亮。
  翻译进度与字符浮起的完成时间跟随同一可视终点，滚动窗口仍依据原展示时间。
- 没有增加只进不退的永久进度缓存；实际回拖播放仍能正确重置。

这针对可由源码确认的分支错位进行修复，不宣称所有播放器的时钟回跳都已定位。
如果复测仍出现抽搐，需同一复现窗口的日志检查播放时间校正，不能用无限钳制掩盖真实 seek。
