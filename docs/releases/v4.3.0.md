# v4.3.0 发布台账

## 发布范围

- Bridge：`4.3.0` / versionCode `141`。
- Provider source：`main`，在 workflow metadata 阶段冻结完整 commit SHA。
- LSP tag：`141-4.3.0`。
- 矩阵：12 个专属 Provider、`universal-provider` 与 `player-readify`，共 14 个 Provider APK。
- 资产：Bridge + 14 Provider APK，共 15 APK；含 Provider ZIP、manifest、`SHA256SUMS`，共 18 项。

## 用户可见变更

- 新增默认关闭的 Salt Player 式字符上浮动画：未唱字符沉在正常基线下方约一个字号的
  10%，揭示前沿经过时沿升余弦升回正常基线并保持；与既有 clip-reveal、羽化和 glow 共用
  时钟。行激活下沉与逐字行收尾窗口均为 240 ms。
- 新增“字符浮动幅度”0–200% 滑块；100% 对应约 10% 字号的下沉，且仅在动画开关开启时显示。
- 开启“普通逐行歌词进度”后，LRC 行时间戳的普通逐行歌词也走整行线性上浮前沿。
- 修复换行多段行的全行前沿：由各段揭示宽度求和，不再钉在首段末端；lift 绘制异常会记录
  `CHAR_LIFT_UNAVAILABLE` 并回退既有整段绘制。

## 架构与兼容边界

Bridge 继续只作用于 `system` 和 `com.android.systemui`，Provider 继续经播放器自身的
`MediaMetadata["lyricInfo"]` 发布数据。本次不改变 Provider 业务行为、不新增私有歌词
传输，也不扩大 Bridge scope。14 个 Provider 均维持 libxposed API 102、静态作用域与
保护性异常策略。

用户已在真机确认逐字歌词（含换行多段行）和开启普通逐行歌词进度后的普通逐行歌词效果。
普通逐行行末约 1.5 个字宽的过渡窗口由既有行切换动画吸收，保持 lift 与羽化前沿严格同步。

## 发布前验证

- Provider 发布契约已更新为 `4.3.0`，并通过 `validate-v5-release-contract.ps1` 与
  `testV5Matrix assembleV5MatrixDebug`。
- Bridge 版本、发布契约、README、发布说明和文档契约已在最终 main 版本通过
  `validate-release-contract.ps1`、`:app:testDebugUnitTest`、`:app:lintDebug`、
  `:app:lintRelease` 与 `:app:assembleDebug`。
- 正式签名 APK 只由 tag workflow 使用受控 secrets 构建；本地构建不作为公开资产。

## 发布后复核

- Bridge commit/tag、Providers `main` 冻结 SHA 与 LSP metadata commit/tag 将在正式 workflow
  完成后记录。
- 分别公开下载 Bridge `v4.3.0` 与 LSP `141-4.3.0` 的 18 项资产，核对文件名、字节数和
  SHA-256。
- 15 个 APK 必须通过冻结发布证书与 `zipalign` 校验；Provider ZIP 只能含 14 个顶层 APK。
