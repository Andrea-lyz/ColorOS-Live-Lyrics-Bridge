# ColorOS Live Lyrics Bridge v4.4.0-C17-Artwork-Preview2

## 简体中文

> 面向 ColorOS 17 的动态封面预览更新，承接 Artwork Preview1。
> 本版为 pre-release，不替代稳定版 v4.4.0，不标记 Latest，不发布到 LSP mirror。

### 动态封面 Provider 1.0.4

- **新增网易云官方动态封面来源**：默认关闭，开启后使用网易云官方客户端扫码确认。会话在应用私有目录加密保存，可随时退出；关闭来源或退出会使旧请求失效。
- **匹配更直接**：AM 优先搜索专辑名，仅在身份未确认时补一次歌曲搜索；网易云搜索曲目名，核对歌手及录音标记后直接使用 songId 请求动态封面。播放器专辑名和时长用于网易云多候选排序，同分仍保持歧义。
- **并发查找，AM 优先下载**：没有可复用视频时，同时准备两路候选；AM 可用就直接下载，AM 最终失败才使用网易云。已验证缓存优先复用，同曲查询及同专辑下载合并，减少亮屏和大小卡切换时的重复等待。
- **网络恢复与状态稳定**：临时网络故障在原有总期限内间隔 1 秒、3 秒补两轮恢复，绕过对应的临时失败缓存。取消、限流、无封面和登录/续期操作不重放。只写整条来源链路的最终结果，避免 AM 的中间失败覆盖网易云成功。
- **独立搜索和封面预览**：AM 与网易云分别使用自己的输入框、按钮及结果，网易云框仅在该来源开启时出现。最近记录给 AM 填专辑名、给网易云填曲目名；修复另一来源结果改写 AM 查询导致 JP Eagles 搜索遗漏的问题。
- **网易云结果显示真实静态封面**，已加载图片可保留到新绑定列表；缓存预览左上角显示 AM / 网易云来源标签。静态缩略图不代表该曲一定有动态视频，绑定仍单独检查。
- **发布前补齐匹配边界**：保留 `(中文版)`、`(粵語版)`、`(重錄)`、`(現場)` 等版本标记；网易云某首歌的失败不再被当作整张专辑无资源，成功视频仍可按专辑共享。旧匹配决策失效，完整视频与手动绑定保留。

### 配套 Bridge 更新

- 封面协议 v1.1 支持最高 **1280×1280** 的原始方形视频，网易云 MP4 不缩放、不转码；AM 继续选取原生 **1080×1080 AVC SDR**。
- 在线资源等待与同曲跨表面保留窗口对齐到 55 秒，覆盖双来源 Provider 的最长 52 秒预算，避免正常冷查询被旧 10 秒判定提前打断。
- 锁屏视图重建或短暂消失时保留同一录音的在途请求，完成后挂载到当前封面；换曲、来源关闭和身份不符仍由现有门禁拒绝。

### 保留能力与兼容范围

保留 C17 原生歌词入口、锁屏小封面/沉浸封面、同步镜像背景、系统模糊与遮罩、封面取色光晕、大封面常亮和本地 TXT 脱敏诊断。AOD 继续使用静态封面。

歌词沿用 `Provider → 播放器 MediaSession["lyricInfo"] → ColorOS SystemUI → 可选 Bridge 增强`。动态封面由普通独立应用匹配、下载和验证，Bridge 消费本地资源，不进入播放器进程。

附带 **Universal Provider 1.1.1 / versionCode 3**，保留既有 C17 `SessionStub.mRecord` 兼容。本轮未修改其业务代码，按固定源码重新构建；其它歌词 Provider 无需全部重装。C16 用户继续使用对应 C16 预览。

### 安装与反馈

1. Root / LSPosed 环境下覆盖安装本页 Bridge，作用域保持 `system`、`com.android.systemui`，按原流程重启。
2. **同时更新动态封面 Provider 1.0.4**；同发布签名的旧版本可覆盖升级，保留设置和绑定。若 Universal 已是 1.1.1，无需为本轮功能重复安装。
3. 在来源应用启用动态封面，并在 Bridge 中选择、授权该来源。网易云需另行开启并扫码登录；默认仅非计费网络下载。
4. 如需反馈，在来源应用“高级”开启脱敏诊断，复现后导出 TXT；显示问题另附同窗口 Bridge 日志，完成后关闭诊断。

Bridge versionName 为 `4.4.0-C17-Artwork-Preview2`，versionCode 保持 144；动态封面 Provider 为 `1.0.4 / 8`。均使用发布证书。Debug 签名包不能按同签名覆盖升级处理；独立 diagnostic 包的私有设置不会自动迁移。

### Dynamic Artwork Provider 1.0.4

- Adds an opt-in official NetEase motion-cover source. Sign in by scanning with the official client; sessions are encrypted in private storage. Disabling the source or signing out invalidates earlier work.
- Searches AM by album first, with at most one song discovery fallback when identity remains unconfirmed. NetEase searches by song title, checks artists and recording labels, then requests the selected song ID's cover. Album/duration help rank candidates; unresolved ties remain ambiguous.
- Prepares both sources concurrently with **AM download priority**. NetEase video downloads start only after AM fails. Verified caches, duplicate-query coalescing and shared album downloads reduce repeat waits; only the final source-chain outcome updates matching status.
- Recovers transient network failures after 1/3-second waits within the original deadline. Cancellation, rate limits, no-cover results and authentication mutations are not replayed.
- Separates AM and NetEase search fields, buttons and results; NetEase appears only while enabled. Recent entries fill AM with the album name and NetEase with the song title. This prevents another source's first hit from replacing the JP Eagles query.
- Shows real static NetEase cover thumbnails and source badges on cached videos. New bindings can retain loaded pictures. Static thumbnails do not imply a motion video is available; binding checks it separately.
- Preserves short native-language/recording labels when handling translated titles. A NetEase song failure no longer excludes its entire album, while verified videos remain shareable. Old query decisions expire without deleting valid videos or bindings.

### Paired Bridge changes

Artwork protocol v1.1 accepts original square video up to **1280×1280**. NetEase MP4s are neither resized nor transcoded; AM remains native **1080×1080 AVC SDR**. Update both Bridge and Artwork Provider.

The online request and same-recording retention budgets are now 55 seconds, covering the Provider's 52-second two-source budget. A keyguard view remount can retain and retarget the same recording's pending asset instead of cancelling it after the old 10-second threshold. Song changes, disabled sources and identity mismatches still fail the existing gates.

### Compatibility and installation

Retains C17 lyric entry support, small/immersive covers, synchronized mirrored backgrounds, native blur/masks, artwork glow, large-cover keep-awake and redacted local TXT diagnostics. AOD remains static. Lyrics still use the player's own `MediaSession["lyricInfo"]`; the standalone artwork app handles networking and Bridge consumes verified local assets without entering players.

Includes **Universal Provider 1.1.1 / versionCode 3** with its existing C17 compatibility, rebuilt from the pinned source without business-code changes. Other lyric Providers need not be reinstalled. C16 users should keep the corresponding C16 preview.

Use Root/LSPosed, install the signed Bridge and Artwork Provider updates, keep Bridge scope at `system` / `com.android.systemui`, and restart as usual. Enable and authorize the artwork source; enable NetEase separately and scan to sign in. Downloads default to unmetered networks. Existing same-signer settings/bindings are retained; debug-signed and independent diagnostic builds are separate. Universal 1.1.1 users need not reinstall it for this update.

Bridge is `4.4.0-C17-Artwork-Preview2 / 144`; Artwork Provider is `1.0.4 / 8`. For feedback, reproduce with the source's redacted diagnostics enabled, export TXT and attach same-window Bridge logs for display issues, then disable logging.

### Validation and limitations

- Locally, Artwork passed 233 tests; Bridge ran 770 with zero failures and 6 existing fixture skips; Universal passed 67; each contract mirror passed 7. Bridge/Artwork debug and release lint report no errors, and Debug builds passed.
- The user confirmed fix9 device testing. The two final audit fixes have regression coverage; the final signed APKs have not received a separate device RC run. Preview delivery does not replace the stable-release RC/device gates.
- The signing workflow reruns tests, release lint, contract checks and package/version/certificate/scope/DEX/zipalign verification. Published downloads are independently checked afterwards.
- Source availability, login state and network conditions still apply. Missing, ambiguous, oversized or undecodable resources retain static artwork. Older 1080 consumers reject 1280 assets above their limits.
- This does not claim to fix the previously observed platform MediaExtractor failures on some C17 beta devices. Full firmware/foldable coverage, long-term power use and official lyric-clock alignment remain incompletely verified.
