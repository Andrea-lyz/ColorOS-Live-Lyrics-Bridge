## User-visible changes

- A lyric that begins with a bracket, such as `[so simple and clean]`, is no longer dropped from the native lyric list. Losing it shifted every later row by one: the following line first lost its live highlight, then the live row drifted to the top edge of the lyric area.
- Measurement, matching, and custom drawing use the committed native row binding, and opening title/artist alias reuse is limited to its recorded slot and text.
- NetEase 9.6.20 display lyrics with an out-of-order tail or a placeholder past the track duration fall back to the decoded ordered timeline.

## Implementation

- `OplusLyricNormalizer` writes the existing zero-width marker between the time tag and a bracketed display text, stopping the vendor parser's consecutive-tag scan without changing visible text, timing, translations, row count, or scrolling.
- `LyricRenderTransactions` exposes an immutable bound row (position, native time, native text) only for the current publication, committed dataset, and real bind owner; `WordLyricModel` resolves by that row and by bound time for repeated text.
- `OfficialLyricFrameResolver` requires an explicitly recorded opening-alias slot and text instead of accepting any slot pointer match.
- `NeteaseLyricInfoPayloadEncoder` rejects non-monotonic host timelines, rows past the known duration, and materially short display lyrics, and sorts all encoded lanes once.
